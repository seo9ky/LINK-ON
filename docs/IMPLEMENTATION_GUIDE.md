# 기획과 구현 기준

이 프로젝트는 **LINK ON: 나에게 맞는 혜택, 알아서 LINK!**의 프론트엔드 시연이다. 1Pager의 서비스 의도, 상세기획 8장의 화면 정책, 최종 Figma 프로토타입의 시각 디자인을 함께 기준으로 삼는다.

## 기획 의도

LINK ON은 필요한 혜택을 알아서 챙겨주는 맞춤 LINK다. 고객이 추천 혜택을 확인하거나 결제 전에 연결하는 일을 놓치는 문제를 줄이려는 제안이다.

최초 동의와 관심 업종 설정 후 적합한 혜택을 고객별 한도 N 안에서 자동 연결하고, 나머지는 직접 선택하게 한다. 직접 LINK 행동에서 얻는 관심 신호를 유지하면서, 추가 구매로 이어지지 않는 할인 비용을 관리하기 위한 설계다.

검증은 기존 LINK와 비교해 자동 연결 혜택의 실제 이용률, 고객이 받은 혜택 금액, 추가 결제 효과, 할인·운영 비용을 함께 보는 방식으로 계획한다. 고객 편의·선택 데이터·수익성의 균형이 기준이며, 성과가 확인되었다고 가정하지 않는다. 발표문의 과거 ‘최초 1개 → 최대 3개’ 기준은 적용하지 않고, 최신 결정인 고객별 한도 N을 따른다.

PDF는 원본의 특정 시점 사본이다. 원본을 수정해도 GitHub 사본이 자동으로 바뀌지는 않는다. 이후 수정할 때 원본 확인 → PDF 재출력 → 코드 대조 → 검증 → 함께 커밋한다. PDF 자체는 GitHub에서 줄 단위 비교가 어렵기 때문에 텍스트 추출본을 함께 관리한다.

1Pager는 원본 Google Docs의 현재 페이지 구성을 보존한 **2쪽**이다. 상세기획은 최종 프로토타입 파일에 배치된 8개 프레임을 순서대로 내보낸 **1920×1080 원본 해상도의 이미지 PDF**다. 텍스트 검색에는 추출본을 사용한다.

## 공통 서비스 원칙

O는 고객 맞춤을 뜻하며 특정 영어 단어의 약자로 확정하지 않는다. N은 동시에 유효한 자동 연결 혜택 수의 상한이다. 고정된 최초 연결 수나 최대 3개·5개 정책은 없다. 적합성과 이용 효과, 할인·운영 비용으로 한도를 정하며 항상 한도를 채우지 않는다.

고객 화면에서는 수학적 표현 대신 **고객별 한도 내**로 안내한다. 나머지 혜택은 직접 선택할 수 있게 유지한다. 이용률 40%와 체감 혜택 +15%는 시험 운영 가정 목표이며 실제 달성 실적이 아니다.

## 화면 정책과 시연 구현

| 항목 | 기획 정책 | 현재 구현·한계 |
| --- | --- | --- |
| 동의 | 최초 동의 후 시작, 미동의 시 진행 불가 | 동의 화면과 시작 버튼 조건 구현. 실제 동의 이력 서버 저장은 없음 |
| 관심 업종 | 선택·저장·변경, 다음 선정부터 적용 | 브라우저에 저장. 다음 시연 선정 시 업종·가상 이용 패턴 반영, 현재 연결은 소급 변경하지 않음 |
| 자동 연결 | 고객별 한도 내 적합 혜택만 선정 | 현재 행사·적합성·제외·예산·연결 오류·고객별 시연 한도로 선정. 기본 2개는 운영 한도가 아님 |
| 자동 혜택 제외 | 이번 행사만 해제하고 같은 행사는 재연결 제외 | 행사 ID별 제외 상태 유지. 11월·12월 동일 가맹점의 별도 행사 선정 구현 |
| LINK ON 끄기 | 새 자동 연결 중단, 기존 혜택은 만료일까지 유지 | 기존 연결 보존. 시연 날짜 변경 시 만료 처리, OFF에서는 신규 자동 연결 중단 |
| 직접 LINK | 고객이 직접 선택·연결 | 자동 연결되지 않은 행사에 직접 연결·해제·재연결. 사용 완료·결제 확인 중인 행사는 중복 이용 제한 |
| 이용 결과 | 완료·확인 중·미적용 및 사유 표시 | 시연 결제 당시 조건 기록 → 확인 중 → 전표 접수 → 적용/미적용. 실결제·전표 API 없음 |
| 문의·오류 | 사유 확인 및 필요한 안내 | 앱의 오류 사유 안내는 유지. 웹 하단 문의 폼은 내용을 실제로 접수하며, 답변 이메일은 선택 입력 |

직접 LINK 해제 기능과 `고객별 한도 내` 표현은 기획서 PDF 이후의 사용자 결정도 반영한 것이다. PDF 원문은 기록 보존을 위해 수정하지 않았다.

## 시연 가정 (운영 정책 확정 아님)

- 가상 이용 패턴과 관심 업종 중 하나라도 일치하면 후보가 된다. 이미 자동 연결된 업종과 겹치지 않는 후보를 먼저 보고, 관심 업종 2점·이용 패턴 1점과 고정된 목록 순서로 선정하는 시연 규칙이다. 업종 다양성은 18개 예시를 보여주기 위한 가정이며 실서비스 추천 모델이 아니다.
- 기본 한도 2, 입력 범위 0~20은 시연 도구 범위다. 실제 N은 확정하지 않았다. 18개 가맹점 모두 자동 선정 후보이며, 자동으로 연결되지 않은 혜택은 직접 선택할 수 있다.
- 한도 축소 시 이미 연결된 혜택은 유지하고 새 연결을 제한한다. 이행 기간에는 기존 연결 수가 새 한도보다 많을 수 있다. 만료 후 새 행사는 새 한도를 따른다. 실서비스의 한도 축소 정책은 별도 확정 대상이다.
- 시연 날짜는 2026-11-03부터 시작하며 도구에서 앞으로 변경한다. 실제 시스템 날짜나 자동 배치가 아니다. 18개 가맹점의 11월·12월 총 36개 시연 행사를 제공한다.
- 동일 행사 1회, 최소 결제금액, 다른 할인 적용 결제 제외는 명시적인 시연 행사 조건이다. 실제 삼성카드 중복 혜택 정책을 단정하지 않는다.
- 결제 접수는 고객의 실제 결제나 청구를 발생시키지 않는다. 전표 접수 버튼은 확인 중인 시연 결제를 일괄 확정한다. 먼저 접수한 적격 결제가 행사 1회 혜택을 예약하며 이후 결제는 중복 적용하지 않는다.
- 결제 시 연결·금액·기간·이용 여부를 기록한다. 결제 이후 연결해도 소급 할인하지 않고, 결제 이후 해제·만료되어도 당시 적격 결제의 결과는 유지한다. 취소·환불·전표 정정은 이번 시연 범위 밖이다.
- 새로고침 후에도 행사별 연결과 결제 기록을 복원한다. 이전 버전의 연결·제외 상태는 이전하되 고정 예시 결과는 실제 시연 결제 이력으로 보지 않아 이전하지 않는다.

## 현재 업종·가맹점

| 업종 | 예시 가맹점 |
| --- | --- |
| 외식 · 간식 | 스타벅스, 공차, 배스킨라빈스 |
| 간편식 · 배달 | BBQ, 도미노피자, 배달의민족 |
| 온라인쇼핑몰 | 쿠팡, SSG.COM, 11번가 |
| 패션 · 스타일 | SSF SHOP, KREAM, 지그재그 |
| 건강 · 화장품 | 올리브영, 아이허브, 닥터나우 |
| 마트 · 슈퍼 · 편의점 | GS25, CU, 이마트 |

최신 사용자 요청으로 확정한 분류다. 기존 PDF의 3개 예시보다 이 표가 우선하며, 고객별 한도·동의·선택권 정책은 바꾸지 않는다. 할인액·최소 결제금액·기간은 시연용 데이터이며 실제 제휴나 제공 혜택을 의미하지 않는다.

기존 저장 데이터의 카페·외식은 외식 · 간식, 편의점·마트는 마트 · 슈퍼 · 편의점으로 이전한다. 예전 온라인 쇼핑 선택은 당시 SSF SHOP 대상이었으므로 패션 · 스타일로 이전한다. 대응 업종이 없는 문화·여가는 선택에서 제외하지만 기존 연결·결제 기록은 보존한다.

Figma 최종 화면은 업종 선택·목록·18개 상세·연결 및 해제/제외 확인창을 확장했다. 초안과 상세기획 슬라이드는 변경하지 않았다. Figma는 고정된 11월 행사와 이용 패턴 예시로 흐름을 보여주며, 웹의 날짜 변경·36개 행사별 결제 판정까지 모두 재현하는 것은 아니다.

## 웹 표현과 기획 자료의 차이

웹 하단의 **문의하기**에서 문의 내용과 선택 입력한 이메일을 접수합니다. Supabase의 별도 문의 테이블에 저장하며, 방문자는 다른 문의를 조회하거나 수정할 수 없습니다. 저장 성공을 확인한 뒤 접수 완료를 안내합니다. 기존 실습 입력 화면과 로그인은 제거했고 이전 데이터는 보존합니다. 설정과 점검 방법은 [문의 운영 안내](INQUIRIES.md)를 참고하세요.

웹의 업종 필터는 18개 혜택을 쉽게 찾기 위한 탐색 기능입니다. 관심 업종·추천 조건·연결 상태를 변경하지 않습니다. 고객 안내는 간결하게 표시합니다. 연결 완료·혜택 상세·메인의 **결제 체험하기**에서 가맹점과 금액을 선택하고, 이용 결과 화면에서 해당 결제의 확인을 완료할 수 있습니다. 두 단계 모두 기존 결제 당시 조건 판정을 사용합니다. 폰 외부의 **시연 설정**은 맞춤 혜택 조건과 행사 시점만 제공합니다. 예외 상황 설정과 일괄 전표 처리 도구는 화면에서 제거하고, 기존 판정 규칙은 유지합니다.

보관된 PDF의 카페·편의점·온라인 쇼핑 예시와 현재 6개 업종은 분류 확장에 따른 차이입니다. PDF를 임의로 덮어쓰지 않고 원본과 이후 결정을 구분합니다. 이번 웹 가독성 개선과 QR 추가에는 Figma·PDF 변경을 포함하지 않았습니다.


## 첫 방문과 결제 체험 — 2026-10-30

- 첫 화면은 서비스 소개·체험 순서와 고정된 시작 버튼을 먼저 보여줍니다. 연결·결제 이력이 없으면 0개·0원 요약을 표시하지 않습니다.
- 기본 관심 업종 두 개는 체험용 예시임을 표시합니다. 사용자가 바꿀 수 있으며, 미선택 시 이용 패턴만 참고하는 정책도 유지합니다.
- 결제 체험은 현재 행사 중 가맹점을 선택합니다. 바로 전 연결한 혜택을 우선하고, 일반 진입 시 미사용 연결 혜택을 먼저 선택합니다. 미연결·사용 완료 혜택도 상태를 알리고 판정 과정을 체험할 수 있습니다.
- 결과 화면의 확인 완료는 해당 결제만 처리합니다. 확인 중 상태는 새로고침 후에도 유지되고, 해제 후에도 결제 당시 적격 조건은 보존됩니다.
- PC는 440×956 비율을 유지하며 창 높이에 맞춰 표시합니다. 폰 외부의 원본 크기·초기화 버튼은 제거했습니다. 모바일은 기존 본문 스크롤과 고정 버튼을 유지합니다.

## 현재 웹 구성

- PC는 왼쪽 브랜드 소개, 가운데 폰 화면, 오른쪽 시연 설정의 3열입니다. 폰의 어두운 테두리와 측면 버튼으로 앱과 웹 설정을 구분합니다. 설정은 글자와 대비를 낮춘 보조 영역입니다.
- 모바일은 소개 → 폰 → 설정 순서이며 앱 본문 스크롤과 고정 버튼을 유지합니다.
- 상단에는 LINK ON 로고와 서비스 소개·기획서 링크, 하단 왼쪽에는 문의하기를 배치합니다. 삼성카드·모니모 로고는 하단 기반 서비스 표시에 사용합니다.
- 관리·상세 이동 버튼은 같은 높이·곡률·여백으로 반응합니다. 기능 없는 카드에는 클릭 효과를 넣지 않고, 버튼은 용도별 호버·누름·키보드 포커스를 구분합니다.
- 문의는 고객 화면의 혜택 상태와 분리됩니다. 열고 닫아도 연결·결제 상태를 바꾸지 않습니다.

## QR

흰색 배경에 기존 LINK ON 로고와 한 줄 소개를 사용합니다. QR 본문은 진한 회색(#292B30), 왼쪽 인식 사각형 두 개는 하늘색(#00AEF3), 오른쪽 위는 핑크색(#EF028D)입니다. 인식 사각형의 바깥 고리와 안쪽 네모는 같은 색이며 인식 여백 밖에 연한 회색 테두리를 둡니다. 이번 웹 구성 변경에서 QR 파일은 수정하지 않았습니다.
