# 문의 운영 안내

웹 하단의 **문의하기**에서 내용을 접수합니다. 내용은 필수(최대 2,000자), 답변 이메일은 선택입니다. 실제 저장이 성공했을 때만 접수 완료를 표시하며, 실패하면 입력한 내용을 남겨 재시도할 수 있게 합니다. 답변 메일 자동 발송 기능은 없습니다.

## 저장과 확인

`src/InquiryDialog.tsx`가 폼을 표시하고 `src/lib/supabase.ts`에서 Supabase `inquiries`에 저장합니다. 관리자는 연결한 프로젝트의 Table Editor에서 문의를 확인하고 필요할 때 직접 답변합니다.

| 항목 | 용도 |
| --- | --- |
| id | 같은 요청을 다시 전송해도 중복 접수하지 않도록 하는 UUID |
| message | 문의 내용 |
| email | 답변을 원하는 경우의 이메일 |
| created_at | 서버가 기록하는 접수 시각 |
| status | received / reviewed / closed. 관리자가 변경 |

브라우저에는 공개용 키만 사용합니다. 행 보안과 열 권한으로 방문자의 접수만 허용하며 조회·수정·삭제·접수 시각 및 처리 상태 지정은 허용하지 않습니다. 문의 내용은 웹의 목록이나 브라우저 저장소에 보관하지 않습니다. 전송 실패 시 같은 창에서 재시도하면 동일한 요청 ID를 사용합니다.

## 환경 설정

`.env.local`에 아래 두 값을 설정합니다. 기존 개발 환경과 Vercel의 공개용 설정을 사용하며 secret/service_role 키는 넣지 않습니다.

```dotenv
VITE_SUPABASE_URL=https://프로젝트주소.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_공개용키
```

`supabase/inquiries.sql`은 새 문의 테이블 최초 생성용입니다. 이미 적용한 환경에 반복 실행하지 않습니다. 이전 `input_db` 테이블과 데이터, 기존 접근 권한은 보존하며 앱에서 실습 화면만 제거했습니다.

## 확인 방법

```sh
npm run build
npm run test:unit
node --test tests/supabase-config.test.mjs
npm test -- tests/inquiry.spec.ts
```

자동 검사는 접수 성공, 대기 중 중복 클릭 방지, 실패 시 입력 보존, 같은 요청 재시도, 모바일 배치, 문의 창을 닫은 후 앱 상태 보존을 확인합니다. 실제 저장 확인은 명확히 검증용으로 표시한 문의 한 건을 보내고 관리자 화면에서 해당 ID만 확인합니다. 공개 키로 다른 문의를 조회할 수 없는지도 확인합니다.

현재 빈 내용·길이·이메일 형식은 서버에서 제한하고 폼에는 자동 입력 탐지용 숨김 필드와 중복 전송 방지를 적용합니다. 요청 횟수 제한이나 봇 인증은 아직 없습니다. 접수량이 늘어나면 서버 요청 제한을 추가하고 문의 보관 기간과 정리 일정을 정해 운영해야 합니다. 공개 화면에는 구현 기술명이나 데이터베이스 조작 버튼을 노출하지 않습니다.
