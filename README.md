# LINK ON · 로컬 프론트엔드 시연

1Pager의 서비스 의도, 상세기획 8장의 화면 정책, 최종 Figma 프로토타입을 함께 기준으로 구현한 React + TypeScript + Vite 시연 앱입니다.

## 기획 자료

- [1Pager PDF](docs/reference/LINK_ON_1Pager.pdf): Google Docs 원본의 현재 2쪽 구성 보존.
- [상세기획 8장 PDF](docs/reference/LINK_ON_Detailed_Plan.pdf): 최종 Figma 파일의 디자인을 그대로 보관.
- [기획과 구현 기준](docs/IMPLEMENTATION_GUIDE.md): 정책 대조, 시연 범위, 변경 시 확인 사항.
- [기준 자료 출처·저장 정보](docs/reference/sources.json): 원본 링크와 파일 해시.

코드 변경 전에 위 자료를 확인합니다. 최신 사용자 결정과 PDF 사이 차이는 구현 기준에 기록하며, 향후 작업자를 위한 규칙은 [AGENTS.md](AGENTS.md)에 있습니다. 원본을 바꾸면 PDF·텍스트 추출본도 함께 갱신해 커밋합니다.

## 실행

이 컴퓨터에서는 `start.cmd`를 실행하면 됩니다. 서버가 이미 실행 중이면 http://127.0.0.1:5173/ 에 접속하세요.

VS Code에서 **파일 → 폴더 열기 → C:\Users\KDA\LINK-ON**을 선택하고 **터미널 → 새 터미널**을 엽니다. 이미 설치된 이 PC에서는 `npm run dev`로 실행하고, 표시된 로컬 주소를 엽니다. 종료는 **Ctrl+C**입니다. `npm`을 찾지 못하면 ` .\scripts\package.cmd run dev`를 사용하세요. 포트가 이미 사용 중이면 기존 실행 화면을 열거나 기존 서버를 종료한 다음 실행합니다.

새로 내려받은 일반적인 Node.js 환경에서는 다음 명령을 사용합니다.

```sh
npm ci
npm run dev
```

Node.js 24 LTS를 권장합니다. 실제 구현·빌드 검증 환경은 Node.js 24.19.0입니다. 새 PC에서는 [Node.js](https://nodejs.org/)와 [VS Code](https://code.visualstudio.com/)를 설치하세요. `node_modules`는 저장소에 포함하지 않으므로 처음 내려받으면 `npm ci`가 필요합니다.

## VS Code에서 열기

1. GitHub 저장소의 **Code → 복사**로 주소를 복사합니다.
2. VS Code 명령 팔레트(`Ctrl+Shift+P`)에서 **Git: Clone**을 선택하고 주소를 붙여넣습니다. 현재 PC에서는 `C:\Users\KDA\LINK-ON` 폴더를 열면 됩니다. `origin`은 `https://github.com/seo9ky/LINK-ON.git`, 작업 브랜치는 `main`이며 `origin/main`을 추적합니다.
3. **터미널 → 작업 실행 → LINK ON: 패키지 설치**를 한 번 실행합니다.
4. **터미널 → 작업 실행 → LINK ON: 실행**을 선택합니다. 브라우저가 열리고 수정 사항이 반영됩니다.
5. 검사하려면 `Ctrl+Shift+B`로 **LINK ON: 빌드 검사**를 실행합니다.

이미 서버가 실행 중이면 [로컬 화면](http://127.0.0.1:5173/)을 열면 됩니다. 같은 서버를 중복 실행하면 포트 사용 중 메시지가 나올 수 있습니다. VS Code에서 서버를 실행한 경우 실행 작업을 종료하면 서버도 종료됩니다. F5의 **실행 중인 화면 디버깅**은 먼저 실행한 서버를 Edge로 엽니다.

Windows에서는 `start.cmd`를 두 번 눌러도 실행됩니다. `scripts/package.cmd`는 일반 Node.js/npm을 우선 사용하며, 이 PC에서 준비한 로컬 도구가 있을 때만 보조적으로 사용합니다. 다른 PC에 Codex 설치는 필요하지 않습니다.

## 변경 이력 저장과 복구

GitHub는 버전 보관용입니다. 파일 저장만으로 GitHub에 올라가지는 않습니다. **수정 → 확인 → 커밋 → 푸시**를 한 묶음으로 진행하세요.

1. 작업 전 VS Code **소스 제어 → Pull**로 원격 변경을 가져옵니다.
2. 작은 변경 단위로 수정하고 화면과 빌드를 확인합니다.
3. **소스 제어**에서 변경 내역을 보고 필요한 파일만 스테이징합니다.
4. `GS25 해제 안내 문구 수정`처럼 구체적인 메시지로 커밋한 뒤 **Push**합니다.
5. 큰 변경은 `feature/변경이름` 브랜치에서 작업한 후 확인된 변경을 `main`에 합칩니다.

처음 동작하는 버전은 커밋 `ca45267c30e20ce6b62154788a8f3ff575cf5b65`로 GitHub에 보관했습니다. 현재 PC에는 `v0.1.0` 로컬 태그도 있습니다(원격 태그는 미등록). 다른 PC에서는 아래처럼 커밋 번호로 동일한 버전을 확인할 수 있습니다. 주요 변경은 [CHANGELOG.md](CHANGELOG.md)에 기록하세요.

```sh
# 최근 저장 기록 확인
git log --oneline --decorate -10

# 특정 변경 취소: 기존 이력을 지우지 않고 취소 커밋 생성
git revert <취소할_커밋번호>
git push

# 최초 버전을 별도 폴더에서 확인: 현재 작업 파일은 유지
git worktree add ../link-on-v0.1.0 ca45267c30e20ce6b62154788a8f3ff575cf5b65
```

강제 푸시나 이력 덮어쓰기 대신 `revert`를 사용하면 변경 기록이 남습니다. 소스 코드의 Git 이력과 브라우저의 LINK 선택 상태는 별개입니다. 선택 상태는 각 브라우저에 저장됩니다.

## 확인할 흐름

1. GS25 혜택 행 → 상세 조건 확인. 오른쪽 `+ 링크`는 Figma처럼 바로 연결 완료로 이동합니다. 상세의 `이 혜택 링크하기`로도 연결할 수 있습니다.
2. GS25 `완료` → 혜택 상세 → 본문의 `이 혜택 LINK 해제` → 확인창에서 유지 또는 해제. 연결된 상세의 하단 버튼은 `LINK 메인으로`입니다.
3. 해제 완료 상태에서 다시 연결. 연결 개수는 매번 함께 갱신됩니다.
4. `LINK ON 시작하기` → 필수 동의 → 관심 업종 선택 → 저장 → 자동 연결 메인.
5. LINK ON 끄기·다시 켜기, 자동 혜택 상세·제외, 관심 업종 저장·취소.
6. 폰 아래 **시연 도구** 펼치기 → 행사·결제금액 선택 → **시연 결제 접수** → 확인 중 → **확인 중 결제 전표 접수** → 적용 완료 또는 미적용 사유 확인.
7. 시연 도구에서 이용 패턴·한도를 저장하고 **새 혜택 선정 실행**으로 다음 선정을 확인합니다. 시연 날짜를 12월로 바꾸면 11월 연결은 만료되고 새 행사만 별도 선정됩니다.

`처음부터 다시 보기`는 앱 바깥의 시연 도구입니다. 이 브라우저의 시연 상태만 초기화합니다.

## 유지한 디자인

- 최종 Figma의 440 × 956 화면, Noto Sans KR, 액션 블루 #1677FF, 원본 LINK ON 로고.
- 스타벅스·SSF SHOP·GS25 원본 이미지, 원본 SVG 아이콘, 상태바와 홈 인디케이터의 배치.
- 카드 그림자, 버튼·알약의 모서리, 문구와 확인창 형태.
- 좁은 화면은 본문 스크롤과 필요한 줄바꿈으로 처리하고 하단 주요 버튼은 고정합니다.
- Figma 원본은 읽기만 했으며 수정하지 않았습니다.

## 상태와 범위

혜택 상태는 `src/model.ts`에서 관리하고 브라우저 저장소에 저장합니다. 직접 LINK를 해제해도 다른 자동 혜택과 LINK ON 설정은 유지됩니다. LINK ON을 꺼도 이미 연결한 혜택은 유지하며, 제외한 이번 행사 자동 혜택은 다시 켜도 복구하지 않습니다.

관심 업종과 가상 이용 패턴을 기준으로 현재 유효한 행사 중 맞는 혜택만 선정합니다. 시연 한도 기본값 2는 변경할 수 있으며 실제 운영 한도가 아닙니다. 적합한 혜택이 없으면 0개입니다. 관심 업종·한도 변경은 다음 선정부터 적용하고 이미 연결한 혜택을 강제로 해제하지 않습니다.

11월·12월 행사를 각각 다른 ID로 관리합니다. 시연 결제 당시 연결 여부, 기간, 최소금액, 행사별 이용 횟수, 중복 할인 여부를 기록한 뒤 전표 접수 시 결과를 확정합니다. 이후 해제·만료되어도 결제 당시 판정과 받은 혜택은 보존됩니다. 실제 추천 엔진, 고객별 한도 산정, 결제·회원 인증·금융 API는 포함되지 않습니다. 구체적인 시연 가정은 [구현 기준](docs/IMPLEMENTATION_GUIDE.md)을 확인하세요.

`public/assets/`에는 실제 사용하는 로고와 아이콘을 보관했습니다. 임시 Figma 다운로드 주소는 앱 실행 시 사용하지 않습니다. Figma 참조 캐시(`design/`), 로컬 검사 결과(`verification/`), 설치된 패키지와 빌드 결과는 Git에서 제외합니다. iOS 공통 요소는 Figma 레이어와 원본 아이콘을 기준으로 웹용으로 구현했습니다.

## 검증

```sh
npm run build
npm run test:unit
npm run test:install
npm test
```

상태·결제 로직 검사 17개와 Playwright 브라우저 검사 14개를 제공합니다. 자동 검사 브라우저는 `LINK_ON_CHROME` 환경 변수로 경로를 지정할 수 있습니다. 현재 환경에서는 독립 브라우저 시작에 실패하여 Playwright 전체 통과는 확인하지 못했습니다. 대신 연결된 인앱 브라우저의 DOM 도구로 주요 화면 이동과 결제·해제 흐름을 실행해 확인했습니다. 이번 검증 범위와 결과는 [v0.2 검증 기록](docs/VALIDATION_v0.2.md)에 기록합니다.

2026-10-30 대조 점검에서 혜택 행/액션 버튼의 동작을 분리하고, 연결 완료 화면의 뒤로가기를 메인으로 정리했습니다. 상세로 다시 들어가 해제했을 때 과거 완료 화면이 재등장하지 않도록 이동 기록을 정리했으며, 상세 주소로 바로 접속해도 앱 안에서 뒤로가기가 가능합니다. 해제 확인창은 배경 스크롤을 고정하고 취소 시 원래 버튼에 초점을 돌려줍니다.

대표 화면 구현 단계이며 자동 배포는 설정하지 않았습니다. GitHub 저장소는 소스와 변경 이력 보관에 사용합니다. 외부 이미지와 폰트 출처는 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)를 참고하세요.
